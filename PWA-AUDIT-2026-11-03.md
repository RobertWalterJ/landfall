# PWA audit, 2026-11-03

App: Landfall. Published at https://robertwalterj.github.io/landfall/ (one shared origin with Robert's other apps).

Jargon: a "service worker" is the small script that lets the app work offline. A "cache" is the phone's saved copy of files. "Manifest id" is the name Chrome uses to tell installed apps apart.

## What was checked

The nine shared-origin rules: manifest id, scope and start_url, cache cleanup, no global caches.match(), manifest never cache-first, icons, storage names, big precache, and navigation handling. Source files and the generated docs/ or site/ folder were both read.

## Findings

| Rule | Result |
|---|---|
| 1 Manifest id | BROKEN. No id. Fixed. |
| 2 Scope and start_url | OK. Both are ".". |
| 3 Cache cleanup | OK. Deletes only landfall- caches that are not current. |
| 4 Global caches.match() | OK. Not used. |
| 5 Manifest not cache-first | OK. Shell files are network first. The manifest is also in the precache but is always fetched fresh when online. |
| 6 Icons | Mostly OK. 192, 512 and maskable 512 exist. In the maskable icon the small orange dot on the right sits outside the central safe circle, so a round mask will clip it. Not changed (needs the icon art regenerated with build/make-icons.py). |
| 7 Storage names | OK. Keys landfall.v1 and landfall.visits. Caches start with landfall-. |
| 8 Big precache | OK. Files are added one by one and failures are ignored. |
| 9 Navigation handling | OK. |

## What I changed

app/manifest.webmanifest: added id "/landfall/" (same as the derived identity from start_url ".").

Rebuilt docs/ with `node build/make-deploy.mjs`. The service worker cache name is stamped by the build, so it changed on its own.

Checks run: build/check-syntax.mjs passed. build/test-engine.mjs said "all invariants held". It also printed "KINDS THAT NEVER BUILT: name-it". That is about the game engine, not this change.

## Does the phone owner need to uninstall and reinstall?

No. The new id matches the old derived identity.
